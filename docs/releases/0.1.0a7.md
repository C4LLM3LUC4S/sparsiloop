# SparsiLoop 0.1.0a7

跟着 PID 示例接入控制器时，保存位置有问题，应该在计算前就知道。这版让源码中的 PID 命令先检查输出路径，再读取配置。已有目录或上级文件会被保留；换一个新目录，就能沿用原配置和增益重试。

## 下载和开始

- **`SparsiLoop-0.1.0a7.zip`**：完整离线包，包含对应源码、安装包、示例和 `START_HERE.md`。
- `sparsiloop-0.1.0a7-py3-none-any.whl`：Python 3.10+ 的核心安装包，不需要第三方运行依赖。
- `sparsiloop-0.1.0a7.tar.gz`：包含修正后 PID 示例的源码分发包。
- `RELEASE_INFO.json` 与 `SHA256SUMS`：核对准确源码提交、文件大小和 SHA-256。旧版本继续保留。

## 保存位置被占用时怎么办？

在完整包的 `source/` 目录中，按 [simple-pid 接入说明](https://github.com/C4LLM3LUC4S/sparsiloop/blob/v0.1.0a7/docs/simple-pid.md)另装固定版本的可选依赖，再运行 `python -m examples.simple_pid_case ...`。如果提示输出已存在，或上级路径不是文件夹，先保留原报告，把 `--out` 改到新目录后重试。配置、PID 增益和随机条件都不需要因为路径错误而调整。

检查发生在配置读取和计算之前，避免无效保存位置先消耗一次实验。后续磁盘空间或权限仍可能变化；不能把提前检查当作保存始终成功的保证。

本次更新位于随包源码示例。已安装核心、PID 适配算法和 `run_case` Python 接口的行为没有改变，也没有向 wheel 加入可选 PID 库。源码文件改动后，新的适配器文件摘要会相应变化；旧报告、旧源码及其摘要照旧保留，不需要修改记录来通过核验。

## English

The optional source-only `examples.simple_pid_case` command now checks its output before configuration reads or PID computation. An existing output or a file-valued parent is rejected early. Keep the original files and retry the same configuration and gains in a fresh directory; no simulation settings need to change just to fix a path.

This release delivers the corrected source recipe and recovery instructions in the full bundle and sdist. The installed core, PID adapter algorithms, `run_case` API and numerical/history formats retain their behavior. The whole example-file digest changes truthfully; old source and records remain intact. The optional pinned simple-pid library is installed separately and is not a core dependency. An early path check does not guarantee later storage availability.

Use the complete `SparsiLoop-0.1.0a7.zip` with Python 3.10+, verify `SHA256SUMS`, and keep matching source. This remains an **alpha prerelease**. Developer checks do not establish independent adoption, human time saved, stability or hardware effects. No PyPI or cloud deployment is included.
