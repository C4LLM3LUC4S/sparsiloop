# SparsiLoop 0.1.0a4

这版补齐了本地独立策略评测的一条恢复路径：测试已经跑完，报告却没保存完整时，先留住这次结果，再重绘报告，不用重新训练或测试。读不完输入文件时，也会给出更具体的处理办法。

## 下载后怎么开始？

- **`SparsiLoop-0.1.0a4.zip`**：推荐首次使用，包含离线安装包、对应源码、示例和 `START_HERE.md`。
- `sparsiloop-0.1.0a4-py3-none-any.whl`：已有 Python 3.10+ 独立环境时安装，核心不需要额外运行依赖。
- `sparsiloop-0.1.0a4.tar.gz`：源码分发包。
- `RELEASE_INFO.json` 与 `SHA256SUMS`：核对源码提交、大小和 SHA-256。

完整解压 ZIP，按顶层 `START_HERE.md` 离线安装。Windows 可用 `(Get-FileHash .\SparsiLoop-0.1.0a4.zip -Algorithm SHA256).Hash` 核对下载；包内 `BUILD_INFO.json` 和 `MANIFEST.json` 标明对应源码和各文件摘要。旧版本与旧记录请继续保留。

## 测试跑完了，报告保存失败怎么办？

本地 `evaluate-policy` 现在先写出并 fsync 完整的 `evaluation.json` 类型结果，再用同一个载入器读回确认，随后生成报告。后面的文件写入失败或中断时，终端会给出保留文件的位置，以及使用本次 Python 的重绘命令。

看到 **Full record retained** 后，先保留那个文件，修好保存位置，再直接使用打印的命令。它把报告写到一个新目录，沿用原结果、失败与未知值、完整策略和已用编号，不生成新的随机输入，不重新训练、评测或计算指标。路径含空格或单引号时，也使用打印出的完整命令。

如果最初的完整副本没写好，或读回校验失败，程序不会承诺可以恢复。保留原输入和已有文件，先检查错误；不要把部分 HTML 或 CSV 当成完整交付。报告成功后若备用副本清理受阻，会提示仍保留的位置，报告仍然有效。

只重绘已有独立评测时，使用完整 `evaluation.json`，例如：

```powershell
python -m event_control_lab.evaluation_report render "old results/evaluation.json" --out "reports/redrawn-evaluation"
```

这个新载入器会读取完整本地 JSON，占用内存；它没有借用 checkpoint 或 planned 文件的容量上限，也没有新增大规模内存保证。它核对保存的结构、原策略与来源、声明条件和随机输入的一致性，不重算结果来认证正确性。缺失的过去执行环境仍是未知。

新的安全 Python 入口是 `event_control_lab.evaluation_report.export_evaluation`。原 `policy.export_evaluation`、控制案例 exporter 和网页临时 ZIP 继续沿用原合同；本版没有新增网页下载恢复，也没有扩大模型或控制算法范围。具体文件用途见[保存与恢复说明](../source-recovery.md)。

## 输入文件读不完时

输入 JSON 嵌套太深时，终端会列出实际文件和原解析错误。保留原件，从生成它的程序重新导出当前命令需要的完整配置、策略或结果；不要压平内容、删历史、只截 Q 表或提高递归限制。后续计算或报告处理的递归错误会单独说明，不会误说成输入文件太深。

## English

The local standalone `evaluate-policy` CLI now writes and fsyncs the complete typed evaluation, reads it back, and only then exports reports. A later I/O failure or interruption retains the actual record and prints a redraw command using the same interpreter. After fixing the save location, redraw into a new directory with the original cases, failures/null, checkpoint, Q table, known IDs and optional original checkpoint-file hash. Redraw does not train, evaluate, simulate, draw new random input or recompute metrics.

An incomplete initial copy or failed readback is never advertised as a usable recovery record. Successful reports remain valid if cache cleanup is blocked. The new full-record loader reads the local JSON into memory; it does not borrow the checkpoint/planned byte caps or promise large-scale memory bounds. Saved structures, source and declarations are checked for consistency, without certifying the numerical results or filling missing past environment information.

Use the explicit new `evaluation_report.export_evaluation` API or `evaluation_report render` command. Legacy Python exporters and temporary web ZIP exports keep their previous contracts. Input-read recursion diagnostics include the actual file and original error; a later computation/export recursion is reported separately. The numerical, policy and historical source identities are preserved.

This is an **alpha prerelease** for local teaching and engineering workflows. Controlled recovery checks do not establish independent adoption, human time saved, hardware effects, stability or recovery after storage corruption/power loss. Earlier releases remain available; no PyPI or cloud deployment is included.
