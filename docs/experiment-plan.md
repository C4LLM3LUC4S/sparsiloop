## 问题与设计

目标使用者是希望理解或接入事件触发控制的学生、教师和研究者。第一阶段回答：在明确的同一上行发送上限、噪声和延迟条件下，能否完整追踪“什么时候发送—控制器看到了什么—误差如何变化”？不预设事件策略一定优于周期策略。

自变量：三个发送策略、阈值、发送上限、固定延迟、丢包概率。固定项：对象、初始状态、反馈增益、积分/采样网格、随机输入、输入限幅、时域与失败上限。结果同时呈现完整时段位置 RMSE 和真实发送数，不合成一个自动冠军分数。

首阶段用两个原创简化对象和固定种子机制验证软件，不进行显著性检验、论文性能复现或真人研究。

## 工程验收

1. 保持常输入的轨迹符合整段解析解。
2. 消息账本守恒；初始消息和丢包占预算，终点消息在途，预算不会超限。
3. 控制器只读取到达的旧测量，丢包或等待期间不会隐含读取真值或计算新输入。
4. 同配置在当前 Python/源码下得到完全相同的结果，各策略共享外部随机轨迹。
5. 短时失败保留轨迹，但完整时域指标不可用；未知观测年龄不冒充零。
6. 从网页选择对象/改参数能走通真实 API，JSON/CSV 可下载，已有命令行输出不覆盖。

命令：`python -m unittest discover -s tests -v`；固定示例：`python -m event_control_lab compare --config examples/default.json --out runs/first`。单次开发验证超时上限 60 秒；输出仅写本项目的 `runs/` 或 `artifacts/`。原课程、RankProbe、私人论文及其仿真参数不改动。
